# M2 ライセンス・照会仕様と操作手順

2027年1月1日のGeneral受付と正本の同時切替に向け、指定種別・発行日・確認移行・照会用CSVの確定部分を整備しました。11月19日に受領したL15も反映し、照会対象とJAF登録名の扱いを更新しています。根拠は共有回答表のC02、N10、N11、L05、L15と、入力文字列に関する依頼者の共通仕様です。今回の配置で受付と正本は切り替えません。

## 確定内容と保留

| 項目 | 今回の動作 | 保留する内容 |
| --- | --- | --- |
| ライセンスの種類 | 指定の競技9種・審判員15種から複数選択。登録画面とGeneral申請で同じ検証を使う | 選択肢の追加は運営確認後 |
| 発行日 | 旧有効期限と別に保持。正しい暦日かを検証し、不明は空欄で保持 | 複数の券面・種別で発行日が異なる場合の入力方法、必須条件はL05で確認 |
| 有効性 | 本人申告として扱い、発行日・旧期限だけで資格・会員証・QRを失効させない | JAFへの自動照会は実装しない |
| 既存情報 | 本人の旧JAF番号と種類を参照。旧自由記載から指定種別を自動推定しない | 本番の実データ移行は実行しない |
| 照会用出力 | JAF指定書式なし。選択年度に有効状態で登録済みのGeneralだけを対象とし、氏名はJAF登録名を使う | 本番ダウンロードは停止。L05の発行日条件とM1の正式入力接続・運営受入は別に残る |
| 受付・正本 | 2027年度はshadow、本人登録・更新と照会CSVは停止 | General受付と正本を同時に切り替える開始判断 |

番号、保有区分、本人所有、所属、承認、満額入金、会員年度、資格停止の条件は維持します。ライセンス情報を登録しただけでは会員資格は有効になりません。競技と審判員は別の登録として、同じ本人番号を保存できます。

## 指定された種類

競技運転者は国際スーパー、国際A、国際B、国際C-C、国際C-R、国際ドラッグ、国際ソーラーカー、国内A、国内Bです。

公認審判員はコース・計時・技術の各A1・A2・B1・B2・B3です。たとえば「コースB1」と「計時A2」を同時に選べます。「なし」はGeneral申請の非保有側だけで選び、保有種別とは混在させません。

全角英数字と全角スペースはサーバー側でも半角へ整形します。Ⅰ・Ⅲなどのローマ数字や、整形対象外の文字は置き換えません。指定外の種類、別区分の種類、重複、配列の入れ子は拒否します。選択順が違うだけの再送では記録を増やしません。

## 画面を見る方法

本番では保存とダウンロードが停止しています。入力項目を確認するための手順です。

1. 事務局アカウントでポータルにサインインします。
2. マイページの「JAF照会用出力の確認」を開きます。出力予定の項目と保留理由を確認できます。
3. 「本人用のライセンス入力項目を確認する」を押します。この画面はログインした本人の情報です。他人の情報は開けません。
4. 「競技の登録」「審判員の登録」で、各選択肢と発行日の欄を確認します。
5. 「既存JAF登録情報を入力欄へ表示する」では、そのアカウントの既存番号と旧種類を参照できます。旧種類は自動選択せず、運転免許の期限を発行日に使いません。

「JAFライセンス登録名」は、JAFへ登録しているカタカナまたはローマ字の名前です。入力欄は照会用として任意にしていますが、未登録者がいる年度のCSVは出力できません。氏名・カナ・エントリー名から自動補完しません。本人ライセンスの保存は停止中で、General申請への正式な追加保存項目の接続はM1の残作業です。

受付開始後は、券面を確認して種類と発行日を入力し、「保存する」で登録します。発行日が不明、または複数券面で異なる場合は空欄にして事務局へ確認してください。発行日の必須条件はL05の回答後に確定します。

General申請でも競技・審判員の両方を指定選択肢から申告します。既存の申告記録は書き換えません。現在は受付停止中なので、申請の操作はできません。事務局向けの架空操作確認も旧期限だけでは資格を失効させない本人申告の方針へ合わせました。

## 既存データの確認移行

技術担当が使うCLIをWeb非公開の `current/scripts/license_migrate.php` に配置しました。ブラウザーから移行を実行する機能はありません。計画はv2形式で、番号を暗号化して保存します。確認ファイルには番号欄を含めず、旧種類を参考表示します。両ファイルは非公開の場所に0600で保存します。

1. 対象DB、実行者の既存ユーザーID、対象ユーザーIDを明示してplanを作ります。
2. 各候補をapprove（移行）かskip（見送り）にし、競技／審判員、指定種別、発行日、不明日付のnull、旧期限、更新対象ID・版を確認します。未確認のpendingが残る計画は適用できません。skipした候補は移行しません。
3. checkで元データ・所有者・重複・確認内容を照合します。checkはDBを書き換えません。
4. 実データの確認と別途の実行判断が済んだ場合だけ、applyに明示の `--apply` を付けます。今回は実行していません。

v1の計画は発行日・指定種別の確認がないため再作成が必要です。旧JAF欄から種別や発行日を推定せず、旧期限・当日・運転免許の情報から発行日を補完しません。元のentrants、アカウント、エントリー履歴は更新しません。計画後の元情報の変更や確認内容の差し替えは拒否し、適用済みの同じ計画を再実行しても二重登録しません。

v2移行ではJAF登録名を推定しません。新規移行の登録名は未登録のままにし、更新対象に保存済みの登録名があれば保持します。

移行の1候補は1区分です。競技と審判員の両方を移行する場合は、区分別の計画に分けて確認します。

技術担当向けの構文例です。M2で始まる4変数を、確認した実際のIDと非公開ファイルパスに置き換えます。保存先ディレクトリは先に準備し、既存ファイルを上書きしません。

```sh
export JMRC_AUTH_BOOTSTRAP=/var/www/vhosts/gymkinki.com/private/jmrc-portal/current/src/bootstrap.php
M2_ACTOR_ID='確認した事務局ユーザーID'
M2_SOURCE_ID='確認した対象ユーザーID'
M2_PLAN='確認した非公開の計画ファイルパス'
M2_REVIEW='確認した非公開の確認ファイルパス'
/opt/plesk/php/8.4/bin/php /var/www/vhosts/gymkinki.com/private/jmrc-portal/current/scripts/license_migrate.php --mode=plan --actor="$M2_ACTOR_ID" --expected-database=jmrckinki --users="$M2_SOURCE_ID" --out="$M2_PLAN" --review-out="$M2_REVIEW"
/opt/plesk/php/8.4/bin/php /var/www/vhosts/gymkinki.com/private/jmrc-portal/current/scripts/license_migrate.php --mode=check --actor="$M2_ACTOR_ID" --expected-database=jmrckinki --manifest="$M2_PLAN" --review="$M2_REVIEW"
```

## JAF照会用出力の準備

CSVは選択した年度で有効状態として保存されたGeneralだけを対象にします。L15によりJAF指定書式はなく、申請中・停止中は含めません。現在の資格の有効・無効やJAFの照会結果を保証するファイルではありません。発行日の入力条件はL05の回答待ちです。

項目は年度、利用者ID、会員資格ID、JAFライセンス登録名、保存された会員状態、JAF番号、競技／審判員、申告種類、発行日、参考の旧有効期限です。住所・生年月日・運転免許・受取人は含めません。登録名と番号は権限確認後に復号し、登録名が未登録、または一部でも復号できなければ全体の出力を中止します。一般の氏名やエントリー名では代用しません。Excel等で保存値が数式として実行されないようにします。

確認画面とダウンロードは、事務局の明示された識別情報取扱権限で制限します。旧管理者・クラブ代表・個人会員の権限だけでは全体出力できません。ダウンロードにはPOST・CSRF・取扱確認が必要で、履歴には年度と件数だけを残します。JAFへの送信は行いません。`license_export_enabled` が未指定またはfalseなら、直接POSTしても停止します。

## 保存と今後の作業

番号の暗号保管、重複確保、更新版、暗号化した変更履歴を維持します。指定種別と発行日、暗号化したJAF登録名は `portal_license_details` に保存し、旧期限と旧情報を自動で書き換えません。種別を変えた場合は旧QRを失効させ、発行日・登録名だけの訂正では失効させません。公開QRに登録名や発行日などの項目は追加していません。

新表もポータルの会員個人情報です。削除設計の対象に含めますが、削除実行は有効にしていません。共通アカウント・既存エントリー・請求入金等を保持する方針は変わりません。

1月1日の開始には、発行日の未確定ルール、M1などの個人情報項目、所属・承認・会費・同時切替を含む総合受入、運営側の開始判断が残っています。今回の完了をM1～M7全体の完了とは扱いません。[11月19日の反映・検証と復元記録](phase2/20261119_追加回答・JAF登録名と会計範囲.md)も参照してください。
