# JMRC近畿 事務局ポータル 運営者確認事項

> 2026-10-27追記: 本文は9月時点の記録です。最新回答を反映した[再確認事項](20261027_再確認事項.md)と[要件更新](20261027_要件更新.md)を優先してください。「回答済み」の表示だけでは確定できない項目も分離しています。

作成日: 2026-09-07
更新日: 2026-09-07

この文書は、`JMRC近畿ポータル仕様案.pdf` に基づき、Webアプリケーション構築前にJMRC近畿運営者へ確認すべき事項と、2026-09-07時点で回答済みの事項を整理したものです。

目的は、2027年初の運用開始に向けて、実装前に業務ルール、権限、会員番号、入金、保険/共済、既存オンラインエントリー連携の判断を確定することです。

## 1. 全体方針

### 未決事項

1. 新ポータルの正式名称は何にしますか。
2. 公開URLは `https://gymkinki.com/portal/` のように新設しますか。それとも既存 `https://gymkinki.com/entry/` 内に統合しますか。
3. 現在の `https://gymkinki.com/` のWixサイトは残しますか。残す場合、どの範囲を新ポータルへ移行しますか。
4. 2027年初に必ず稼働させる機能と、後日でよい機能を分けてください。
5. GO/NO GO判断日はいつにしますか。

## 2. アカウント・ログイン

### 回答済み

1. 既存オンラインエントリーのエントラントアカウントは、そのまま個人会員ポータルでも利用する。

### 未決事項

1. 既存オンラインエントリーの主催クラブアカウントを、正会員クラブ代表アカウントとして利用してよいですか。
2. 1人が複数権限を持つケースはありますか。例: エントラント兼クラブ代表、事務局員兼エントラント。
3. 事務局員、事務局長、副委員長、委員長、運営委員、財務委員の権限差をどう定義しますか。
4. 承認者は誰ですか。PDF案では事務局長、代理は副委員長とされていますが、最終承認は委員長ですか。
5. メールアドレス変更、退会、アカウント統合、代理登録を認めますか。

### 設計メモ

- 既存 `jmrckinki.users` を共通ログイン基盤として扱う。
- 現行の `role_id` だけでは、個人会員、エントラント、オフィシャル、クラブ代表、財務委員、事務局員、承認者を十分に分けられないため、ロール追加または権限テーブルが必要。

## 3. 正会員クラブ

### 回答済み

1. クラブコードは「5桁固定 + 区分1桁」の6桁体系で確定。
2. 区分桁は先頭に置く。

### 未決事項

1. 正会員クラブの区分は、公認、加盟、準加盟、賛助の4区分で確定ですか。
2. 先頭区分桁と、公認/加盟/準加盟/賛助の対応表を確定してください。
3. 既存のクラブコードから新体系へ変換が必要ですか。
4. 正会員クラブ登録時の必須項目を確定してください。
5. クラブ登録/更新の入金額、支払期限を確定してください。
6. クラブ代表の変更手続きはポータル上で行いますか。
7. 準加盟/賛助クラブに表示するメニューや権限は正会員と同じですか。

### 設計メモ

- 表示上のクラブコードは `区分1桁 + 固定5桁` として扱う。
- 固定5桁はクラブ固有番号として不変にする。
- 区分変更が発生しても固定5桁を維持できるよう、DB上は固定部と区分部を分けて持つのが安全。

## 4. 個人会員

### 回答済み

1. 個人会員区分ごとの年会費は仮確定。
2. `Entrant` と `Official` は2,000円。
3. `Autotest` は500円。
4. 年度によって変更可能にするため、年会費は年度別マスターで保持する。

### 未決事項

1. 個人会員区分は `Entrant`、`Official`、`Autotest` の3区分で確定ですか。
2. ライセンスなしでも個人会員登録可能とする方針で確定ですか。
3. 運転免許証番号は必須ですか。オートテスト/オフィシャルでも必須ですか。
4. JAFライセンス番号とJAFライセンス種別は任意ですか、競技区分によって必須ですか。
5. 個人会員はクラブ所属を絶対条件とする方針で確定ですか。
6. 他地区JMRC所属者の扱いをどうしますか。
7. 退会、年度更新、登録情報変更の承認要否を決めてください。

### 設計メモ

- `membership_fee_master` のような年度別マスターを作り、区分、年度、金額、有効期間、表示順、有効/無効を管理する。
- 会費額は申請時点のスナップショットとして請求明細にも保存し、後年のマスター変更で過去請求額が変わらないようにする。

## 5. 所属クラブ申請・承認

### 未決事項

1. 個人会員は、当該年度に承認済みの正会員クラブ一覧から所属クラブを選択する方針でよいですか。
2. 個人から所属申請があった場合、クラブ代表が承認/却下する方針でよいですか。
3. クラブ側の事前登録名簿と一致した申請は自動承認する方針でよいですか。
4. 事前登録の一致条件は何ですか。氏名、フリガナ、生年月日、免許証番号、メールアドレスのどれを使いますか。
5. 却下時に理由入力は必要ですか。
6. 年度途中の所属クラブ変更を認めますか。
7. 複数クラブ所属を認めますか。
8. クラブ代表が閲覧できるクラブ員情報の範囲は、第11章では「すべて」と回答済みです。運用上もこの前提で確定してよいですか。

## 6. 個人会員番号・デジタル会員証

### 回答済み

1. 個人会員番号は、現行システムに近い `JAFライセンス番号-クラブコード` で確定。

### 未決事項

1. JAFライセンス番号がない個人会員の番号体系をどうしますか。特に `Autotest` と `Official` の扱いを決めてください。
2. 会員証に表示する項目を確定してください。
3. 会員証の有効期限は年末 `12月31日` で確定ですか。
4. 会員証はPDF出力も必要ですか。それともスマホ画面表示で足りますか。
5. 会場確認用のQRコード/検証URLは必要ですか。
6. JAF近畿地域クラブ協議会印影、ロゴ、表示文言の正式データを提供してください。

### 設計メモ

- 会員番号は `JAFライセンス番号-クラブコード` を正式値として保存する。
- クラブコードが先頭区分桁を含む6桁になるため、会員番号に含めるクラブコードも6桁コードを使う前提。
- JAFライセンス番号なしの登録を認める場合、会員番号の代替採番ルールが必須。
- デジタル会員証には、少なくとも年度、会員番号、氏名、所属クラブ、入会日、有効期限、証明文、検証用情報を持たせる。

## 7. 共済・スポーツ安全保険

### 回答済み

1. スポーツ安全保険の加入条件は「個人会員のみ」で確定。

### 未決事項

1. 初回申込は4名以上、追加申込は個別随時可能で確定ですか。
2. ノンライセンス者の加入条件を確定してください。
3. オートテスト参加者は、主催クラブ臨時会員として当日保険加入にしますか。
4. スポーツ安全保険の申請書フォーマット、提出先、提出方法を確定してください。
5. 加入者証のデジタル表示は必要ですか。
6. 共済とスポーツ安全保険は別制度として画面上も分けますか。
7. JMRC近畿見舞金の申請フロー、必要書類、承認者、支払記録を確定してください。

### 設計メモ

- スポーツ安全保険申請画面では、個人会員資格が未成立のユーザーを申請不可にする。
- クラブ代表による加入者一覧、初回4名以上チェック、追加申請、申請書出力が必要。

## 8. 入金・決済

### 回答済み

1. 正会員クラブ、個人会員、スポーツ安全保険、共済、見舞金関連の入金先口座は登録可能にする。
2. ペイメントコアはすべての入金対象で利用可能にする。
3. 金融機関CSVは、既存 `jmrckinki` でも利用しているゆうちょ銀行形式を対象にする。
4. 入金名義ルールは、送金者名義の後ろにエントラントIDを付ける。
5. 事務局と財務委員の入金確認権限は分けない。どちらも入金確認可能。
6. 入金確認終了後の修正権限も、事務局と財務委員が持つ。

### 未決事項

1. ペイメントコアの連携方式は、URLリンクだけですか、決済結果CSV/API連携まで必要ですか。
2. ゆうちょ銀行CSVのサンプルを提供してください。
3. 入金不足、過払い、返金、振替、現地精算の運用を確定してください。
4. 正会員クラブ登録費など、エントラントIDを持たない支払いの名義ルールを決めてください。
5. 入金先口座を事務局側で複数登録する場合、用途別、年度別、支部別のどこまで分けますか。

### 設計メモ

- 汎用の入金先口座マスターを作り、用途、年度、有効/無効、振込先表示名、口座情報、ペイメントコアURLを管理する。
- 汎用請求テーブルを作り、クラブ費、個人会員費、スポーツ安全保険、共済、見舞金関連費を同じ入金消込UIで扱う。
- ゆうちょCSV照合では、名義末尾のエントラントIDを抽出して請求へ紐づける。
- エントラントIDを持たない請求には、クラブID、申請ID、請求番号などの代替照合キーが必要。

## 9. 情報発信・資料BOX

### 未決事項

1. 旧HPから移行するページ、PDF、リンクを一覧で提供してください。
2. ハンドブック廃止後にポータル掲載するコンテンツを確定してください。
3. 一般公開、個人会員限定、クラブ代表限定、主催クラブ限定、運営委員限定、事務局限定の公開範囲を定義してください。
4. お知らせ投稿者は誰ですか。
5. メール配信対象グループを定義してください。
6. 代表者会議、表彰式、運営委員会、委任状/出席確認のオンライン化範囲を確定してください。
7. 添付ファイルの保存期間と削除方針を決めてください。

## 10. 既存オンラインエントリー連携

### 回答済み

1. 個人会員情報は、新ポータルの個人会員情報を正本にする。
2. 個人会員費・共済の支払い済み判定は、ポータルの年度資格を正とする。
3. 既存 `view_annual_jmrc_payments` は、エントリー受理済み情報からの算出ではなく、ポータル請求/入金情報へ置き換える。
4. 過去エントリー履歴は新ポータルのマイページに表示しない。
5. 練習会申込やフォーラムはポータルに統合しない。

### 未決事項

1. エントリー時、ポータルの所属クラブ承認がない場合は申込不可にしますか、それとも警告にしますか。
2. 既存エントリーの主催クラブ機能と、正会員クラブポータル機能を同一アカウントで扱いますか。
3. 既存エントリーの `entrants` に残る個人情報と、ポータル正本との差分が出た場合の同期タイミングを決めてください。

### 設計メモ

- 既存エントリーは、個人会員情報、所属クラブ、年度資格、共済支払い済み状態をポータルから参照する。
- 既存 `view_annual_jmrc_payments` は、ポータル側の年度資格/請求/入金テーブルを参照するビューまたは互換APIへ置き換える。
- 過去エントリー履歴をポータルに表示しないため、マイページは会員情報、年度資格、所属、会員証、申請/入金状態に絞る。
- 練習会申込とフォーラムは現行システム側に残し、ポータルMVPの範囲外とする。

## 11. セキュリティ・個人情報

### 回答済み

1. クラブ代表が閲覧できる個人情報の範囲は、クラブ員に関する全項目とする。
2. 免許証番号、生年月日、住所、受取人情報をCSV出力できる権限は、クラブ代表とJMRC管理者に限定する。
3. 操作ログの保存期間は3ヶ月。
4. ステージング環境へ本番データを使う場合、マスキングは不要。
5. バックアップ保存期間、復元テスト頻度、障害時連絡先は随時決定する。

### 未決事項

1. 個人情報の訂正、削除、退会時の扱いを決めてください。
2. クラブ代表が「全項目」を閲覧できる対象は、自クラブ承認済み会員のみですか。申請中、却下済み、退会済みも含みますか。
3. CSV出力ログ、出力ファイルの保存期間、再ダウンロード可否を決めてください。
4. 操作ログ3ヶ月経過後の削除方法を決めてください。自動削除か、管理者手動削除か。

### 設計メモ

- 個人情報閲覧範囲が広いため、クラブ代表の閲覧/CSV出力/詳細表示は必ず監査ログに残す。
- ステージングでマスキング不要とする場合でも、ステージングURL、Basic認証、IP制限、管理者アカウント管理は本番同等に扱う。
- 訂正、削除、退会の推奨初期案は、本人訂正申請、事務局承認、退会後ログイン停止、会計/監査に必要な範囲のみ保持、画面上は非表示、という論理削除方式。

2027年初運用開始に向けたMVPとして、次を必須にする案です。

1. 共通ログイン
2. 正会員クラブ登録/更新申請
3. 事務局による正会員クラブ承認
4. 個人会員登録/更新申請
5. 所属クラブ申請
6. クラブ代表による加入承認/却下
7. クラブ員事前登録による自動承認
8. 年度別個人会員/所属/共済/スポーツ安全保険状態
9. 年度別会費マスター
10. デジタル個人会員証
11. 入金先口座マスター
12. ゆうちょ銀行CSV取り込み
13. ペイメントコアURL管理
14. 既存オンラインエントリーへの会員状態連携
15. 事務局からのお知らせ

後続フェーズでよい候補:

1. 旧HP全面移行
2. ハンドブック全コンテンツ移行
3. 運営委員会資料BOX
4. 表彰式/代表者会議の出欠・委任状
5. JMRC近畿見舞金申請の完全オンライン化
6. 高度な問い合わせ管理
7. ペイメントコアAPI自動連携

MVP対象外として現行維持するもの:

1. 過去エントリー履歴のポータルマイページ表示
2. 練習会申込
3. フォーラム

## 14. 判断が遅れると影響が大きい項目

### 確定済みまたは仮確定済み

1. エントラントアカウントは個人会員ポータルでも利用する。
2. クラブコードは先頭区分1桁 + 固定5桁。
3. 個人会員区分ごとの会費は年度別マスターで管理する。
4. 個人会員番号は `JAFライセンス番号-クラブコード`。
5. スポーツ安全保険の加入条件は個人会員のみ。
6. 個人会員費・共済の支払い済み判定はポータル年度資格を正とする。
7. `view_annual_jmrc_payments` はポータル請求/入金情報へ置き換える。
8. 練習会申込とフォーラムはポータル統合しない。

### 引き続き早期判断が必要

1. 新ポータルURLと既存HP/Wixの扱い。
2. 主催クラブアカウントと正会員クラブ代表アカウントの共通化可否。
3. 先頭区分桁とクラブ区分の対応表。
4. JAFライセンス番号がない個人会員の会員番号体系。
5. 所属クラブ承認がないエントラントの申込可否。
6. 初回4名以上などスポーツ安全保険の詳細運用。
7. 個人情報の訂正、削除、退会時の扱い。
8. ペイメントコアの連携方式。
9. 2027年初MVP範囲とGO/NO GO基準。
