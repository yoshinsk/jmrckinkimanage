## 認証・公開の境界

- 既存の `profiles.correct` を、従来の操作確認と同じ事務局確認権限として毎要求で検査する。編集・公開の業務権限は新設しない。権限取消後は次の一覧・詳細要求を拒否する。
- 匿名は401、会員・クラブ代表・旧entry管理者など確認権限のないアカウントは403。確認画面のGETだけを許可し、POST・PUT等は405と `Allow: GET` を返す。
- カタログとテンプレートはWeb公開領域の外に置く。表示内容をエスケープし、参照URLはHTTP(S)、ホスト、認証情報・制御文字の有無を検査する。元HTMLを実行しない。
- `no-store`、`noindex`、CSP、フレーム禁止、Referrer-Policyを設定する。検索はGET、サインアウトは既存のCSRF付きPOSTだけ。
- 公開記事テーブル、保険帳票、会員・申込・会計サービスへ接続しない。DDL、受付設定、年度切替、通知、公開承認は変更しない。共通認証の通常の監査・セッション処理は継続する。

## 検証手順と結果

```powershell
python tests/auth/validate_auth.py
python tests/information/validate_offline.py
```

隔離HTTP検証は使い捨てMariaDB・PHP-FPM・nginx、外部公開ポートなしのinternalネットワークで行う。既存entryの必要なソースだけをコピーし、実設定・実データを使わない。公開前の画面は受付保留にした隔離設定でも確認する。

配布版はネットワークなしのコンテナで再生成し、Chromium／WebKitで検証する。確認対象は分類・元年度・キーワード・部会、参照元の折り畳み、予定の種別、日本時間、320～1,280px、文字200％、44px以上の操作対象、権限取消・不正入力・GET以外の拒否。
