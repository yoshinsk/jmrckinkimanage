# スポーツ安全保険の申請・指定Excel出力

2026-10-29。確定済みの加入意思受付・クラブ/事務局による帳票出力を実装し、加入審査・保険料・補償期間は保留する。本番未適用。

## 根拠と実装範囲

出典は[運営者回答表](https://docs.google.com/spreadsheets/d/1z0WuTupTRBSXgzMNBRjosTNgOi13HyVPYtn1knIsato/edit)のGEN-01、INS-01/03、MEM-06備考、R09/R10と、追加PDFのp6。個人会員に加入意思を記録してもらい、クラブ代表・事務局が一覧と指定様式を出力する。

R09が未回答のため、料率・保険期間・初回4名の単位・ノンライセンス/Temporaryの加入可否・取消/返金条件は確定しない。General/Temporaryの本人登録に対する「加入意思」を受け付けるが、Temporaryの加入を承認したことにはならない。未入金・所属承認待ちでも意思は記録でき、会員資格と保険加入資格を混同しない。停止・却下・年度終了の会員登録は受付・出力を保留する。

保険料請求、入金済み判定、保険加入の有効化、外部への申請送信、加入者証発行は実装対象外。R10の協議会見舞金・部会救済基金から資格や入金を転用しない。既存portal_scheme_enrollmentsのactive行も作成しない。

## 利用手順

`/manage/insurance.php`で本人の会員登録を選び、加入意思を確認して記録する。同じ会員登録への再送は重複を作らない。複数Temporary登録間を自動統合せず、保険の重複審査は条件確定後の工程とする。

クラブ代表・事務局は対象年度クラブを選び、申請一覧から1～24件を選択してExcelを出力する。24名は指定様式の行数による技術上の上限で、加入最低人数ではない。25名以上は複数回選択して確認票を作成する。初回/追加加入の判定や正式な提出単位は未確定。

出力はすべて「確認用・提出不可」。帳票出力で提出済み・加入済みへ遷移しない。申請者数と保険加入者数は同じ意味ではない。

## 指定様式と項目対応

原本は[指定Excel](http://www.jmrc-kinki.net/_userdata/sports.security.insurance_form_club.xlsx)をハッシュ固定して保存。[原本管理](../../templates/insurance/README.md)を参照。

| 出力セル | 内容 | 取得元/保留理由 |
| --- | --- | --- |
| E5 / T5 / E6 | クラブ名・6桁コード・担当者名 | 年度クラブ登録。クラブ名未設定時のみクラブマスターを参照 |
| Q6 | 担当者携帯電話 | 空欄。登録済み一般電話を携帯とみなさない |
| C11:C34 | 氏名 | 最新portal_profilesの姓・名 |
| G11:G34 | ふりがな | 最新プロフィールのカナ。自動変換しない |
| M11:M34 | 性別 | 登録値が男/女に対応する場合のみ。未登録/その他は空欄 |
| N11:N34 | 生年月日 | 最新プロフィール。未登録は空欄 |
| R11:R34 | 個人会員番号 | 現在有効・発行済みのGeneral会員証から取得可能な場合のみ。未発行・Temporaryは空欄 |
| B11:B34 / Q11:Q34 | 保険区分・年齢 | 保険開始日・判定条件未確定のため空欄 |
| 掛金・人数別計算・振込欄 | 金額等 | 空欄。原本の旧料率・計算結果を残さない |

記入例を削除し、加入条件・料率が確認待ちであることを明記する。既存の書式・結合・列幅・行高・印刷設定を保持する。文字列はinlineStrとして書き、氏名が`=`等で始まっても数式にしない。未登録項目を推測やダミーで補完せず、個人情報訂正の手続きを新設しない。

## 権限・記録・障害時

既存の事務局（global）とクラブ代表（対象club）に`insurance.export`を明示付与する。旧role_id、財務専用、全クラブを対象とするCLUB_REPのglobal grantは許可しない。所属変更後の旧クラブは出力できず、本人の再申請で新所属へ記録を移す。権限取消・会員停止・却下を要求ごとに再確認する。

`portal_insurance_requests`に意思確認と対象会員/年度クラブを保存する。出力時は`portal_insurance_exports`と`portal_insurance_export_items`に原本ハッシュ、出力ハッシュ、担当者、対象ID・版を記録する。帳票本文を監査ログやDB履歴へ保存しない。ファイルは非公開の0600一時ファイルで処理し、応答後の再ダウンロード用に永続保存しない。記録の削除・保存期間は既存の未確定事項を踏襲し、自動削除を追加しない。

申請・出力はPOST+CSRF、応答はno-store。原本不一致・ZIP/DOM拡張なし・生成失敗・監査失敗ではファイルを返さず停止し、DB処理をロールバックする。

## 導入候補と検証

追加DDLは007とinsurance_permissions.sql。Web非公開に原本を置き、設定`insurance_template`に絶対パスを指定する。PHPのpdo_mysql・openssl・zip・domが必要。`insurance_intents_enabled`は既定falseで、意思受付のみを開始できる。既存001～006やjmrckinki原本を書き換えない。

隔離検証は`python tests/auth/validate_auth.py`。架空データ、internalネットワーク、公開ポートなしで実行する。本人限定・CSRF・再送・権限/所属変更・監査失敗・未確定課金/加入の不変をHTTPで検証し、独立Python実装でZIP/XML・原本パーツ・最終行・式注入防止を照合する。Chromium/WebKitでは本人申請と事務局の実ダウンロードを検証する。Excelのネイティブアプリでの印刷・外部保険機関の受理は未検証で、正式提出も行わない。

原本・1名・24名の確認出力をSpreadsheetsの描画で目視確認する。原本の末尾空白付きシート名を描画ツールが扱えないため、描画専用の一時複製のみ名前を正規化する。アプリ出力のシート名・書式は原本どおりで、原本workbook.xmlの一致を独立検証する。

最終検証結果: HTTPS 486項目、QR/画面更新23項目、指定Excel独立照合32項目、実ブラウザー38項目、合計579項目PASS。PHP構文確認64ファイル。Chromium 156.0.8078.4（Pixel 7相当）とWebKit 27.2（iPhone 13相当）で本人申請・事務局の実ダウンロードを確認した。実ダウンロードのXMLでも氏名と有効なGeneral会員番号の一致を確認した。正式な加入処理・本番適用は未実施。
