# Generalのデジタル会員証・QR資格照会

> 後続実装: [ライセンス登録更新・暗号移行](20261028_ライセンス登録更新・暗号移行.md)を追加し、スマートフォン相当の実ブラウザーでも検証しました。以下の「実ブラウザー未検証」等は会員証実装時点の記録です。物理端末カメラ・実データ移行は引き続き未実施です。

2026-10-28。General本人のデジタル会員証と、QRによる匿名の資格照会を実装しました。本番・既存jmrckinki原本は変更していません。

## 本人には会員証、匿名照会には資格の真偽だけを表示する

[確定要件](../20261027_要件更新.md)のCARD-02〜04に基づき、Generalの会員証には年度・会員番号・クラブ略称・ライセンス種類・QRを表示します。Temporaryには発行しません。会員番号は申請時に選択した本人のライセンス番号と現在の承認済み所属から、`ライセンス番号-G-6桁クラブコード`で生成します。

[追加回答](../20261028_追加回答の反映と対応方針.md)のR13は未回答です。匿名照会で返す情報は`active: true/false`だけに制限しました。氏名・会員番号・ライセンス番号・年度・クラブ名・ライセンス種類・期限・無効理由は公開しません。会員証の追加項目も保留しています。

この照会は現在の資格を確かめるもので、QRを提示した人の本人確認までは行いません。公開表示項目の確定後、本人確認との対応方法を改めて検討します。

## 本人が年度を選び、発行する

1. 共通アカウントでログインし、`/manage/card.php`からGeneralの年度を選びます。
2. 現在有効な資格なら「会員証を表示・発行する」を押します。POSTとCSRF検証後に番号とQRを発行します。同じ申請への再操作は同じ番号・同じ有効QRを返します。
3. 会員証のQRを読み取ると`/manage/card-check.php`で現在の資格を照会します。ログインは不要です。
4. QRを失効させる必要がある場合は、本人がその年度の「QRを失効する」を押します。再度発行すると同じ会員番号に新しいQRを結び付け、旧QRは無効のまま残します。会員資格の取消にはしません。

会員証の参照・発行・失効は本人だけが行えます。事務局・財務・クラブ代表という理由で他人の会員証を表示・発行する機能は追加していません。GETだけでは番号やトークンを作成しません。

## 入金・承認・停止・期限を照会ごとに確認する

本人の会員証参照と匿名照会は、どちらも`Eligibility::evaluate()`で正本を確認します。保存されたactive状態やQRの存在だけでは有効と判定しません。

| 変更・状態 | 本人の会員証 | 発行済みQRの照会 |
| --- | --- | --- |
| 個人会費またはクラブ年会費が訂正により不足 | 番号・QRを返さない | 無効 |
| 申請/所属承認取消、クラブ年度条件の不成立 | 表示停止 | 無効 |
| 資格停止、本人アカウント停止、メール未確認 | 表示停止 | 無効 |
| 年度/所属の期間外、ライセンス期限切れ | 表示停止 | 無効 |
| 将来年度 | 発行しない | 有効にしない |
| QR自身の期限切れ・本人による失効 | 対応QRを表示しない | 無効 |
| 再充当や停止解除で条件が復旧 | 現在の条件で再評価 | 失効・期限切れでない同じQRは再評価可能 |

ブラウザーは表示中も15秒間隔で再照会し、無効・通信障害時には有効表示を消します。本人画面では会員番号とQRも消去します。タブを隠した場合や履歴から戻った場合も再確認します。サーバーの照会結果はキャッシュさせません。

印刷物や保存画像には、その後の資格変更は反映されません。印刷・画像保存後はQRで最新資格を確認してください。紙面にはQR照会を求める案内を残します。

## 採番元の変更時は自動再発行しない

R02の再発行理由・旧番号の扱いなどは未確定です。既存のライセンス選択と番号体系の確定部分だけを使い、別ライセンスを自動選択する処理や再発行ルールは追加しません。

発行時のライセンス情報・種類・所属年度コードを認証付きの指紋として保存します。元情報が変わった場合や番号が終了した場合は、旧QRを無効にして事務局確認を求めます。履歴だけがある会員への自動再採番も止めます。

ライセンス暗号文の再暗号化でも指紋は変わります。将来の鍵更新やデータ移行では、同じ値かどうかの確認と再発行方針の確定が必要です。実装側で旧番号を自動承継する仕組みは設けていません。

## QRに個人情報を埋め込まず、URL断片を使う

QRの内容は`https://gymkinki.com/manage/card-check.php#<256ビットの不透明トークン>`です。ライセンス番号・会員番号・ユーザーIDを直接の照会キーにしません。

トークンはURLの`#`以降に置き、通常のHTTPリクエストURLへ入りません。照会画面のJavaScriptが断片を読み取り、アドレスバーから除去して同一オリジンの`card-verify.php`へPOSTします。Cookieやリファラーを送らず、外部QR生成API・CDNも使用しません。

トークンの平文はDBへ保存しません。検索用SHA-256と、本人への再表示用の認証付き暗号文を保存します。会員番号も暗号化し、番号照合にはHMACを使います。監査・通知予約には番号・トークン・ライセンス平文を含めません。匿名照会は台帳を書き換えず、セッションCookieも発行しません。

未知のトークン・失効・資格不足は同じ最小の無効応答にします。DB障害等は503とし、有効のまま扱ったり、確定的な無効と偽装したりしません。Webサーバー・WAF等でもPOST本文のトークンをアクセス記録や解析サービスへ転送しない設定が必要です。

QRは[Project Nayukiの生成ライブラリ](https://github.com/nayuki/QR-Code-generator)をローカル配信して生成します。取得元・ライセンス・固定ハッシュは[資材記録](../../public/manage/assets/README.md)に記載しました。

## 隔離環境でサーバー判定と実QRの復号を検証する

開発機でテスト専用の固定依存を用意し、統合検証を実行します。Nodeは検証専用で、本番PHPアプリには不要です。

```powershell
npm.cmd ci --prefix tests/card --ignore-scripts --no-audit --no-fund
python tests/auth/validate_auth.py
```

既存の認証・個人会費・クラブ年会費の回帰検証に加え、本人制限、CSRF、再送・同時発行、入金訂正、停止・期限切れ、採番元変更、失効・再発行、障害時ロールバックをHTTPS/PHP-FPM/MariaDBで確認します。DBは架空データのみで、Docker internalネットワークに公開ポートはありません。

QRは実際のSVGパスを画素化し、生成側と異なる[jsQR](https://github.com/cozmo/jsQR) 1.4.0で復号してURLの一致を確認します。本人画面・匿名照会の更新や通信障害時の消去はNodeのDOM模擬環境で検証します。生のトークンURLは最終検証記録へ保存しません。

結果は[検証記録](../../tests/auth/validation_result.json)を参照してください。実ブラウザーの外観、スマートフォンカメラ、実ライセンスの復号、実決済、通常の競技会申込完走は未検証です。R13の公開項目とR02の再発行方針は、運営者への確認を継続します。
