# 運用準備画面の検証と復元

## 対象

開発作業T01～T05のうち、確定要件で接続できる確認画面と、受付停止を前提とした通常の役職申請・承認画面を追加する。[実装仕様](20261103_運用準備仕様.md)と[事務局の確認手順](../20261103_運用準備確認ガイド.md)を参照する。

本番の変更対象は以下の6ファイルに固定する。

| ファイル | 扱い |
|---|---|
| `src/Operations/PreparationService.php` | 新規。確認用のDB参照。 |
| `src/Auth/StaffRoleService.php` | 既存。本人の役職・承認対象の読取を追加。 |
| `src/bootstrap.php` | 既存。新サービスを読込。 |
| `public/manage/preparation.php` | 新規。事務局の運用準備確認。 |
| `public/manage/staff-roles.php` | 新規。通常の申請・相互承認。本番は停止中の読取だけ。 |
| `public/manage/index.php` | 既存。確認画面へのリンク。 |

DB定義・業務記録・権限・設定ファイル・既存entryの変更は含めない。復元対象も上記だけとし、SQLによる復旧は行わない。

## 隔離環境

実データ・本番設定を持ち込まない内部Dockerネットワークで、PHP 8.4.27、MariaDB 10.5.29、既存entryの必要なソースのコピーを使用した。公開ポートは設けていない。

`python tests/auth/validate_auth.py`で2,868項目が成功した。内訳はHTTP・業務処理1,120項目、ブラウザー1,748項目。PHP構文109ファイルと、参照した既存entryのソース不変も確認した。結果は`tests/auth/validation_result.json`に保存する。

追加範囲では、他者・自己承認・CSRF・更新版衝突・承認後再送の拒否、クラブ年会費と入会金の分離、再加入の扱い、実イベントとの明示対応、照会期間の時刻境界、未切替年度の判定保留、個人情報の件数のみの表示を確認した。運用準備のGET前後で、監査ログを除く全業務表のチェックサムが変わらないことも確認した。

Chromium・WebKitでは、JavaScript無効、幅320・390・844・1,280px、文字200%で新画面を確認した。一般エントラントへの拒否、停止中の役職操作ボタン非表示、共通サインイン・サインアウトも確認した。

## 配置・復元の手順

`scripts/deploy_information_preview.py`の`preparation`プロファイルを使う。配置直前のファイルSHA、保護対象のソース・設定、業務表チェックサム、件数、年度設定、停止フラグが計画時と同じ場合だけ適用する。試験済みファイルのSHAと配布ファイルのSHAも一致させる。

既存3ファイルを非公開ディレクトリにバックアップし、新規3ファイルと既存3ファイルを限定配置する。PHP構文検査と対象ファイルのOPcache更新を行う。配置途中で失敗した場合は、旧ファイルを復元し、新規ファイルと新設した空の`src/Operations`だけを撤去する。既存サービス全体の再起動は行わない。

手動復元では、今回のバックアップ内の`deploy_information_preview.py`を、同じバックアップディレクトリを指定して実行する。

```sh
sudo python3 <今回のバックアップ>/deploy_information_preview.py --rollback <今回のバックアップ>
```

復元処理は現在のSHAも検査する。後続の変更がある場合は停止し、自動で上書きしない。復元後にログイン、マイページ、既存の操作確認・情報ページ、受付停止を再確認する。業務記録や設定を戻す操作は不要であり、行わない。
