# 正会員クラブの年度登録・承認・年会費

2026-10-28。正会員クラブの年度登録、年会費請求、入金確認後の事務局承認、個人会員資格との連携を実装しました。本番・既存jmrckinki原本は変更していません。

この資料はクラブ代表・事務局・財務担当者と導入担当者向けです。初回は「登録から有効化まで」を確認し、金額設定・移行・検証の節は必要時に参照してください。

## 登録から有効化まで

1. `/manage/clubs.php` で担当クラブと年度を選びます。前年以前の直近情報があれば名称・代表・連絡先を入力欄へ引き継ぎます。クラブの振込先口座は再表示せず、継続使用か新規入力を選びます。
2. 正式名・略称、区分、代表者、連絡先担当者、郵便番号・住所・電話・メール、振込先を確認して登録します。受付開始・締切は年度マスターに従います。区分は1=公認、2=加盟、3=準加盟、6=加盟団体。既存クラブの不変5桁に先頭区分を付けた6桁コードを生成します。
3. 年度登録の詳細から「年会費請求を表示・発行」を実行します。同一クラブ・同一年度は1登録・1請求です。年度・区分の料金と入金先を請求発行時に保存します。
4. 事務局または財務担当者が `/manage/billing.php` で請求を選び、入金額・銀行取引番号を確認して充当します。クラブ代表自身による入金確認は許可しません。
5. 満額入金確認後、事務局が年度登録を承認します。クラブ代表・財務だけの権限では年度承認できません。承認済みでも、将来年度は年度開始まで有効になりません。

入金不足では承認できません。過入金は必要額だけを充当し、残りは未充当で保持します。決済URLへの移動だけでは入金確認済みにはしません。

### 年度内のコードは固定、連絡先は訂正可能

登録後は年度・クラブID・区分・コードを変更できません。次年度は同じ不変5桁を使い、区分を変更して新規登録できます。休止・退会操作を必須にせず、過去の年度登録を残します。

正式名・略称、代表・連絡先、振込先は詳細画面で訂正できます。更新版数を照合し、別の担当者の変更を上書きしません。請求先口座の発行時記録は、クラブ登録情報の訂正に連動して書き換えません。

## 年会費額は年度・区分ごとに設定する

**実際のクラブ年会費額は確認待ちです。** 確定金額を推測して初期設定していません。年度・区分の金額や入金先が未設定、または有効な設定が複数ある場合は請求を停止します。検証に用いた12,000円・8,000円は架空の料金です。

| 設定先 | 設定内容 |
| --- | --- |
| `portal_fee_rules` | `year`=対象年度、`purpose_code=club_fee`、`member_type=club_1/club_2/club_3/club_6`、`charge_unit=year`、金額、有効期間、enabled |
| `portal_bank_accounts` | `purpose_code=club_fee`、対象年度または共通、有効期間、口座暗号文、任意のHTTPS決済URL |
| `portal_years` | 年度資格の開始・終了、クラブ受付開始・締切、正本モード |

会費額・受付日・入金先の設定は導入担当者が行います。金額や入金対応が不明な場合は事務局へ確認し、未確認のまま入金済みにはしません。無料区分を自動で有効化する規則は追加していません。

クラブが登録する振込先と、JMRCが年会費を受け取る口座は別の情報です。前者をクラブ年度情報に、後者を請求の入金先として保管します。

## クラブと個人の入金を分けて資格を判定する

年度クラブは、申請承認・年会費満額充当・有効な区分・portal正本年度が揃ったときに登録条件が成立します。年度内である場合に現在有効と判定します。期間は開始時刻を含み、終了時刻を含みません。

個人会員は、従来の本人確認・ライセンス・所属承認・個人会費・年度/イベント期間の条件に加え、所属クラブ年度の承認と年会費満額充当も確認します。クラブ会費を支払っても個人会費の代わりにはなりません。個人会費だけを支払ってもクラブを有効にしません。

クラブ年会費を訂正して充当不足になると、クラブ状態と、そのクラブ年度に承認済みで所属する個人会員を同じトランザクションで再判定します。個人の入金記録を消さずに資格を無効とし、元のクラブ請求へ再充当して条件が戻れば資格も復旧します。訂正理由と元の入金記録を保持します。

画面・資格参照は毎回 `ClubEligibility` / `Eligibility` で判定します。保存statusだけを資格確認に使わないでください。区分停止、口座の入金記録失効、年度経過などの変化も参照時に反映します。

用語: `paid`は満額の会費充当、`approved`は申請承認、`ready`は期間以外の条件成立、`active`は現在有効です。先行受付の承認と現在の有効資格は分けます。

## 権限と口座情報の保管

- 年度登録・訂正・閲覧は、自クラブの明示された代表権限、または事務局の登録権限が必要です。旧JMRC_ADMIN/CLUBのrole_idやコード一致だけでは付与しません。
- 年度承認は事務局の明示権限です。事務局職員の任命・承認者に関する未回答事項を、今回の権限追加で確定扱いにはしません。
- 入金確認と確定後訂正は既存の `billing.confirm` / `billing.correct` を用い、事務局・財務の双方に対応します。財務にはクラブ連絡先等の登録情報の閲覧権限を自動追加しません。
- クラブ振込先はAES-256-GCMで保管します。鍵はWeb非公開設定の `data_key`、設定例では環境変数 `JMRC_PORTAL_DATA_KEY` にBase64形式の32バイト鍵を指定します。鍵が未設定なら新しい口座を保存せず停止します。

口座の平文・暗号文はHTTPや監査へ返しません。継続時は前年度の暗号文を引き継ぎます。鍵はバックアップと復旧に必要です。今回の実装は`gcm1`形式で、鍵のローテーションや旧形式からの変換ツールは別工程です。

## 既存クラブの移行は入金照合後に行う

承認済みという状態だけを取り込んでも、会費の証跡がなければ年度クラブ・個人資格を有効にしません。その登録へ年会費を自動再請求することも止め、事務局照合を求めます。既存の支払いを推測して付け替える処理はありません。

移行対象の年度クラブについて、元の請求・入金・承認・口座情報を確認し、正しい台帳へ対応付ける必要があります。過去の承認済みクラブを新ルールのもとで無条件に維持する仕組みは設けていません。この照合は本番適用前に完了させてください。

新規クラブの不変5桁の採番、既存主催者アカウントとの対応付け、担当者へのgrant付与は運営の確認を伴うマスター整備です。代表が任意のクラブIDやコードで別クラブを作る操作は提供していません。
