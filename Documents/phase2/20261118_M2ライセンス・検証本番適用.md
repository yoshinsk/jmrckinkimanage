## 実装

発行日は旧有効期限と別に保存し、不明はnullにします。必須条件と複数券面の異なる日付の持ち方はL05で確認中です。旧期限・当日・運転免許から発行日を補完しません。発行日だけの訂正で会員証・QRを失効させず、番号・種類の変更では既存の再発行待ちの扱いを維持します。公開QRへ発行日等の項目は追加しません。

移行CLIはv2計画と明示確認を使います。種類・発行日・旧期限・元データ・所有者・更新版・重複を照合し、checkは書き込みません。applyは明示フラグを要し、全件成功時だけコミットします。事務局向けの照会CSV作成処理は権限・CSRF・明示確認・復号失敗・数式対策・最小の操作履歴を検証しました。正式書式と対象範囲はL15で確認中のため、本番ダウンロードは無効です。

旧操作確認画面に残っていた自由記載の架空種別と、旧期限だけで資格を失効させる判定も確定方針へ揃えました。ライセンスの有効・無効はシステムでJAFへ確認せず、本人申告として扱います。会員年度・所属・承認・満額入金・資格停止などの条件は残しています。

## 非公開原本と復元手順

DBの原本・定義・チェックサム・適用記録・CLIの保存先です。

```text
/var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/license-details-db-20261118-20261118T090839Z
```

コード原本・配置スクリプト・manifestの保存先です。

```text
/var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/license-m2-20261118-20261118T090900Z
```

両フォルダーは0700、保存ファイルは0600です。配置は検証済みハッシュだけを受け付け、後続の変更があれば上書きしません。PHPのキャッシュは対象ファイルだけを失効させ、本番サービスを再起動しません。

1. 技術担当が対象ハッシュ・保留設定・後続のデータや権限変更を確認します。後続変更があれば自動で戻しません。
2. 必要な場合だけ、先にコードを復元します。

   ```sh
   sudo python3 /var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/license-m2-20261118-20261118T090900Z/deploy_information_preview.py --rollback /var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/license-m2-20261118-20261118T090900Z
   ```

3. 追加表に記録がなく、適用後のDB状態が保存記録と一致する場合だけ、追加表とこの表への追加DML権限を復元します。

   ```sh
   sudo /opt/plesk/php/8.4/bin/php /var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/license-details-db-20261118-20261118T090839Z/database.php --rollback
   ```

4. サインイン、既存entry・ダート、ポータル画面、保留設定、業務件数・チェックサムを読み取りで照合します。DB全体を上書きしません。

復元は隔離環境で検証済みです。本番で試験目的の巻き戻しはしていません。後続記録を削除して復元条件を満たす操作は禁止します。
