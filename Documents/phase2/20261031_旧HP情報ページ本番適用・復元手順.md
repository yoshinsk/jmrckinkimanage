# 旧HP情報ページの本番適用・復元手順

適用日時：2026年10月31日22:06 JST。ブラウザー確認：22:07 JST。既存データ・設定の再照合：22:08 JST。

本番の [/manage/](https://gymkinki.com/manage/) から、事務局だけが旧HP情報ページの試作を閲覧できるようにした。一般公開、登録受付、年度資格の切替、未確定項目の実運用は開始していない。DB・設定・権限・既存アカウントは変更していない。

## 事務局の確認手順

1. 既存アカウントで `/manage/` にサインインする。
2. 「事務局の設定」→「旧HPの情報ページを確認」を開く。「機能の操作確認」からも入れる。
3. お知らせ、資料・制度の案内、統一カレンダー、部会・関連リンク、引継ぎ対象を確認する。

認証付きのURLは `/manage/information-preview.php`。権限は既存の `profiles.correct` を毎リクエスト照合する。本番ではこの権限を持つロールは `OFFICE` だけで、有効な付与先は1アカウント。既存entryの管理者権限だけでは閲覧できない。新しい権限は付与していない。

未ログインは401、事務局権限のないアカウントは403となる。情報画面は閲覧専用で、記事保存・公開・アップロード・申請・送信の操作はない。既存のサインアウトだけはCSRF付きPOSTを使う。詳しい見方は[確認ガイド](../20261031_旧HP情報ページ確認ガイド.md)を参照する。

## 復元手順

バックアップは次の非公開ディレクトリ。ディレクトリは0700、元ファイル・manifest・復元スクリプトは0600で保存した。

```text
/var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/information-preview-20261031T130628Z
```

対象には元の `src/bootstrap.php`、`public/manage/review.php`、`public/manage/index.php` と、配置前後のハッシュ・所有者・モード・保護状態を記録した `manifest.json` を含む。本番確認後の `verification.json` も同じ場所に保存し、転送用の一時ディレクトリは撤去した。復元スクリプトのSHA-256は `bb8f3ade797e5ad72a97eb50cf343e170ab6cd0b3860be984b000dc71305abf4`。

1. `vps2.sugokura.com` に管理用SSHで接続する。
2. 対象ファイルに後続の変更がないことを確認し、次を実行する。スクリプトも全対象のハッシュと復元原本を、書き換え前に照合する。

```sh
sudo -n python3 /var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/information-preview-20261031T130628Z/deploy_information_preview.py --rollback /var/www/vhosts/gymkinki.com/private/jmrc-portal-backups/information-preview-20261031T130628Z
```

3. `status: PASS`、`rollback: true`、`protected_state_unchanged: true` を確認する。元の3ファイルが戻り、新規5ファイルだけが撤去される。新規の `Content` ディレクトリは空の場合だけ削除する。
4. `/manage/` と `/entry/` のサインイン・サインアウト、既存の事務局設定画面を確認する。旧HP試作へのリンクは消え、試作URLは404になる。

対象ファイルの後続変更、バックアップの破損、`current` の切替、symlinkを検出した場合は停止する。対象外のファイルや後続作業を巻き戻すためにハッシュ検査を外して実行しない。

適用処理中に失敗した場合は自動復元する。復元中にも異常があれば `rollback_failed` を記録し、キャッシュ済みコードが必要とする非公開の依存ファイルを残す。原因を確認した後、同じ復元コマンドで完了させる。初回導入用スクリプトやDBリストアは、この表示変更の復元には使わない。
