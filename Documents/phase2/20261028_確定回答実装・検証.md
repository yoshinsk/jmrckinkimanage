## 日付・承認・課金を分けた

UTCのイベント開始日時から日本時間の参加日を生成し、会員申請の日付との一致も外部キーで検査します。日本時間で翌日0時ちょうどに終わるイベントは、終端排他的な1日として扱います。年境界でもUTCの年をそのまま対象年度にしません。

申請時点で日付を確保し、同日の別申請は承認待ちでも拒否する実装を採用しました。同じ申請の再送は日付を追加確保しません。却下/中止時の解放や複数日イベントは未確定のため、解放機能を設けず、複数日イベントのTemporary申請は事務局確認として拒否します。

主催クラブ承認は申請と所属の承認を記録し、当日0時から翌日0時までの期間を保存します。**承認だけで会員資格をactiveにはしません。** 入金確認前はpendingです。請求・消込は別工程です。

TemporaryとGeneralは別申請とし、Temporaryからの自動切替・差額計算・500円の充当・返金を実行しません。当日取消機能も追加していません。主催者中止時の対応は別途確認が必要です。

## 隔離検証

[再現用スクリプト](../../tests/auth/validate_auth.py)で、HTTPS/nginx・PHP-FPM 8.4.27・MariaDB 10.5.29を専用Docker internalネットワークに起動。公開ポートなし、架空データのみ、DBはtmpfs。実行後にコンテナとネットワークを削除します。

既存99項目に新しい会員ルール72項目を加え、**171項目すべてPASS**。PHP構文確認は30ファイルで成功しました。各ケースとソースSHA-256は[機械可読結果](../../tests/auth/validation_result.json)を参照してください。

| 検証 | 結果 |
| --- | --- |
| 競技/審判員によるGeneral申請 | 受付成功、未入金pending |
| 免許のみ/他人/空/期限切れ/未分類 | 受付拒否、失敗時に申請/所属/監査/outboxを残さない |
| 正式クラブ区分/年度コード固定/連絡先訂正 | 正常値を受付、不正値とコード変更を拒否 |
| 同日別イベント・参加日改竄 | HTTP/DB双方で拒否 |
| 別接続・同人・同日で異イベントに同時申請 | 201が1件、409が1件。敗者に孤児申請を残さない |
| UTC/JSTのずれ・年越し・翌日0時終端 | 正しい日本時間の参加日・資格期間 |
| 主催者承認/他クラブ/globalのみ/権限取消/CSRF欠落 | 対象クラブの明示権限だけを許可 |
| 申請/承認の再送 | 一件の記録と通知予約を維持 |
| 既存entryのログイン/ログアウト/権限 | 旧99項目を維持、原本ソースのSHA-256が不変 |
