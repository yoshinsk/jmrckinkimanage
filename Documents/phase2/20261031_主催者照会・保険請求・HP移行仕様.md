主催者の照会は、サーバー側で「イベントID→旧主催者→確認済みportalクラブ→担当者権限」と「entry ID→対象イベント・users.id」を検証する。URLのイベントID、club_id、user_id、画面上の役割選択を権限根拠にしない。共同主催や未対応クラブは確認待ちにする。照会・保存・帳票・ダウンロードすべてに同じ制約を適用する。

現在の操作確認画面で使う `profiles.correct` は、この新機能群を実データで操作する権限に流用しない。

## 4. スポーツ安全保険の請求連絡

### 4.1 入力と加入確認

資料で確定できる連絡内容は「被保険者名」「クラブ名」の2項目。本人のアカウント、保険申込／加入の内部ID、年度、受付番号、作成・送信時刻はシステムで記録する設計案とする。被保険者名・クラブ名は対象の申込情報を提示し、相違がある場合は事務局の確認対象にする。自由入力した氏名だけで別の加入者へ結び付けない。

`portal_insurance_requests`の加入意思やExcel出力履歴だけを加入済みの証拠にはしない。正式加入記録・旧加入の確認証跡がある場合と、未確認の場合を画面上で分ける。Q01の回答前は、架空データによる確認と下書きまでを実装可能範囲とする。

事故日・事故概要・連絡先・証明書等はQ03の確認対象。資料にない医療・受取口座情報を先回りして必須項目にしない。現在の会員資格が切れているという理由だけで過年度加入分の連絡を一律拒否する設計にせず、対象期間・申請可能期間を確認する。

### 4.2 状態案

`draft → submitted → received → completed`。修正が必要な場合は `received → returned → submitted`。送信後の取消はQ03で運用を決める。

- submitted: ポータルが事務局への連絡を受け付けた状態。
- received: 事務局担当者が内容を確認し、受領した状態。
- completed: 事務局の連絡対応が完了した状態。保険会社の支払決定を意味しない。

送信前に「事務局への請求連絡」を確認表示する。送信ごとの一意キーで再送を防ぎ、同一人の別事故を年度単位の一意制約で排除しない。事務局の差戻し・訂正・完了は理由と更新版を確認し、業務記録と監査を同一トランザクションで保存する。

メール通知は担当者・文面・送信設定の確定後にoutboxへ接続する。再試行で受付番号を増やさない。請求連絡から保険料の請求書・入金・給付金を作成しない。協議会見舞金・部会基金の処理を呼び出さない。

## 5. 参加者資格照会の連携契約

提案サービス名: `EventEligibility.readForOrganizer(actor, legacy_event_id, entry_id)`。既存と同じPHP共通サービスを第一案とし、匿名APIは作らない。

| 項目 | 戻す内容の案 |
| --- | --- |
| 対象 | 対象イベント・entry ID、必要最小限の参加者識別表示 |
| 個人会員 | 登録状態、General／Temporary、有効性。申請ありと有効資格を別項目で返す |
| 所属クラブ | 対象年度、所属クラブの登録状態・有効性。イベント主催クラブとは別項目 |
| 根拠 | portal／legacy／shadowの参照元、取得時刻、規則版、判定できた／確認待ち／取得失敗 |
| 理由 | 「承認確認待ち」等の業務上の最小分類。詳細な入金・口座・住所等は返さない。公開項目はQ05 |

ポータル年度が正本に切り替わっていない場合は、比較結果と正式な判定を分ける。対応付けが未確認、履歴が不足、DB障害のときは「未加入」と決め付けず確認待ち／取得失敗にする。自動再請求、申込取消、参加資格の自動拒否には接続しない。

会員・クラブの現時点の有効性は既存サービスを使う。入金訂正、所属・クラブ承認の取消、資格停止、期限切れを次の照会へ反映する。ただし、`Eligibility.evaluate(id, 過去日時)`へ日時を渡しても、当時の入金・所属等の全履歴が復元されるわけではない。開催時の根拠が必要な場合は判定時点の証跡を保存し、不足した過去分は事務局確認とする。

Temporaryの主催クラブによる承認と当日資格を扱えるようにするが、ポイント付与対象になるとは推定しない。公開QRは従来どおり有効時の氏名・会員番号に限定し、主催者向け情報や判定理由を公開応答に加えない。

## 6. シリーズポイントと確定履歴

処理の単位は「年度→競技部会→シリーズ→イベント／開催回→クラス→選手または組」。シリーズとクラスを区別し、同じクラス名でもシリーズ・年度が違えば別集計とする。選手の識別は内部IDを用い、表示氏名・会員番号を集計キーにしない。

流れは「原リザルト取得→本人照合→資格根拠確認→規則版による計算→担当者確認→確定→承認済み項目の公開」。Q07～09が未回答の部分は計算・確定を保留し、仮の点数を正式順位として表示しない。

採点規則は年度・シリーズ・版を持つ。順位別点数、有効戦数、同点処理、完走／不成立／失格、クラス変更、資格判定の基準日を規則として固定する。規則書の保存先とハッシュを記録し、採用した規則の出所を残す。既存の20点方式は再利用候補であり、新規マスターの既定値にしない。

既存リザルトを取り込む場合は、イベント・取込版・行位置・内容ハッシュ・元IDを証跡として保持する。同じ内容の再取込では二重加算せず、訂正版は新しい版として扱う。氏名候補が複数・未解決の行は確認対象とし、無言で合算・除外しない。対象外選手を順位詰めして得点するかも規則の確認事項である。

確定時に原結果版、本人対応、資格根拠、規則版、各戦得点、採用戦、合計、順位、確認者を記録する。後日入金・資格・リザルトが変わった場合は「再確認が必要」を付け、確定結果を自動で書き換えない。訂正理由と承認を経て新しい確定版を発行する案とし、具体的な適用条件はQ08～09で決める。

既存のゼッケン割当、過年度順位、イベント申込の処理は別の受入対象とする。新集計を接続するだけで従来の割当順位が変わらないことを確認する。

## 7. 公開情報・資料・カレンダー

インフォメーションは「事務局」「運営委員会」「全国JMRC」「JMRC近畿」の分類に、年度・競技部会・情報種別を組み合わせる。発行団体と表示分類は別項目にする。シリーズ表彰者、JAF CUP、西フェス、代表者会議、講習会、レンタル機器等を探せるようにする。

記事は `draft / review / published / archived`、本文と添付は版管理する。公開承認者はQ10で決める。旧HPに公開されていた情報は公開移行候補とし、新規の内部資料や記入済み名簿まで公開対象へ広げない。運営委員会の公開決定事項と、非公開の資料BOXは別画面・別権限で扱う。

公開資料と個人情報を含む保険帳票は保管・配信経路を分ける。既存の `portal_documents` は保険帳票等の生成履歴を持つため、記事添付を一括で公開する用途へ転用しない。添付は拡張子だけでなくMIME・容量等を検査し、HTML／スクリプトを実行可能な状態で配信しない。限定資料は直接URLでも認可し、期限切れ後のキャッシュに注意する。

統一カレンダーには競技会、会議、事務局在席／休業日を種別付きで登録する。競技会は `portal_events` と旧イベントの対応を使い、会議や休業日のために競技会レコードを作らない。日時・終日・Asia/Tokyo・更新元・公開範囲・中止状態・詳細リンクを持ち、元の予定と移行先の予定を二重表示しない。

JAF規則等は公式ページへのリンクで案内する。自動スクレイピングや同期は今回の要件に含めない。旧HPのHTTPリンクは元URLとしてそのまま記録し、未確認のHTTPS URLへ機械的に置換しない。公開するリンクの到達性・転送先は切替前に確認する。

| `portal_content_assets`・`portal_external_links` | 添付の非公開保管キー・ハッシュ・MIME・版・閲覧範囲、リンク先・説明・最終確認日。記事公開時にも添付の範囲を再確認 |
| `portal_calendar_items` | 種別、日時／終日、公開範囲、更新元キーUQ、競技イベント参照任意、状態、版 |
| `portal_legacy_content_map` | 元URLと内容区画、移行先／外部リンク／除外の分類、元年度・版、対応HP番号、確認者・日時、転送案・実施状態。元URL一つを複数記事へ分割可能 |

`portal_`という候補名はポータル共通領域に置く案を表す。シリーズ関連の物理的な保存場所はQ06に合わせて決め、entryとportalの双方に更新可能な正本を作らない。

請求連絡・証跡・添付に含まれる個人情報は、既存の暗号化・監査方式に合わせる。操作ログ2年、ドラフト3か月の方針と、給付に関する連絡記録・確定結果の保存期間は別に決める。未更新者の個人情報削除が新しいスナップショットへ及ぶ範囲、匿名化後の集計再現性、バックアップ復元後の再削除はQ03・09と既存の削除設計で整理する。既存共通ID・entry・会計・操作ログを連鎖削除しない。

## 9. 旧HPの移行手順

1. [URL台帳](../20261031_旧HP移行元URL台帳.csv)に、資料P番号、HP番号、元URL、年度、引継ぎ先、担当者、公開範囲、回答を記録する。今回の候補抽出後も、トップから到達する下位ページと添付の棚卸しが必要。
2. 旧HP管理者から原本ファイルと更新権限を確認する。各ファイルの版・年度・公開可否・ハッシュを照合する。旧ページ内の価格や申込先を新年度仕様へ自動転記しない。
3. 公開記事、部会への案内、JAF等の外部リンク、ポータル申請への案内、移行対象外に分類し、非公開のプレビューで運営確認する。
4. 実際の移行先URLを決定し、本文内リンク、PDF／Excelへの直リンク、画像、同一ページ内の区画、各部会からのリンクを検証する。
5. 旧ドメイン管理者が転送できる場合のみ対応表に従い設定する。設定できない場合は旧ページの移転案内を依頼する。全旧URLを一律にログインへ転送しない。廃止アンケートのファイル削除やサイト全体削除は行わない。
6. 切替前のHTML・ファイル・転送設定と公開版をバックアップし、公開単位ごとに切り戻せるようにする。既存entryのログイン・申込URL、会員・会計の正本はこの移行処理で変更しない。

旧HPトップのHTML取得とリンク抽出を実施した。全リンク先の本文・ファイル内容・到達性、旧サーバー設定権限は未確認。旧HTMLを新サイトへそのまま埋め込み、既存スクリプトを実行する方式は採用しない。

## 10. 隔離環境の受入条件

以下は次の実装工程で行う検証項目であり、今回の実行済みテストではない。

| ID | 検証 | 合格条件 |
| --- | --- | --- |
| AT-01 | 共通認証と役割取消 | 既存ユーザーが従来の資格情報で利用でき、取消後は次の要求から新業務を拒否 |
| AT-02 | 主催・イベント・参加者のID差替え | 担当外イベント、他人の申込、未承認の主催対応を拒否。リンクを隠すだけで済ませない |
| AT-03 | 会員資格と所属クラブ | 未入金、承認待ち、クラブ未成立、所属変更、停止、期限切れを区別し最新照会へ反映 |
| AT-04 | 年度未切替・対応不明・DB障害 | 正式な有効判定にせず確認待ち。未加入と誤判定した再請求・申込取消をしない |
| AT-05 | 過去資格とTemporary | 証跡不足の過去状態を断定しない。当日資格と年度メニューを分け、得点対象は確定規則に従う |
| AT-06 | 請求連絡の所有・代理 | 本人の対象だけを表示。クラブ代理は明示許可と対象範囲が必要 |
| AT-07 | 意思登録と正式加入 | 意思・Excel出力だけで加入済みや給付確定を表示しない。過年度の扱いはQ01の確定条件で検証 |
| AT-08 | 送信再試行・競合 | 同じ送信で受付番号が増えず、別件は登録可能。古い版・CSRF欠落を拒否し、障害時は一括取消 |
| AT-09 | 個人情報・制度分離 | 生の氏名・事故内容を一般監査や公開応答へ流さない。請求連絡から会費・保険料・他制度の請求を発行しない |
| AT-10 | リザルト再取込・同名・別シリーズ | 二重加算、同名合算、別年度・別クラス・併催シリーズの混在を防ぐ |
| AT-11 | 正式な採点規則 | Q07の規則書による既知の結果と各戦点数・採用戦・合計・同点順位が一致 |
| AT-12 | 確定後の資格・入金・結果訂正 | 再確認が必要な対象を特定し、承認なしに公表版を上書きしない。訂正版の根拠を再現可能 |
| AT-13 | 既存ゼッケン割当の回帰 | 新しい照会・集計を無効にした場合も従来結果が一致。旧結果の無断書換えなし |
| AT-14 | 公開・限定記事と添付 | 公開決定事項だけが匿名閲覧可能。非公開委員会資料・個人帳票は直URLでも拒否 |
| AT-15 | 移行元の年度とリンク | 台帳と元ファイルが一致し、旧料率・旧締切・旧年度結果を現行として表示しない |
| AT-16 | カレンダーと旧HP移行 | 種別・JST日付・中止が正しく、元予定の重複なし。除外対象と移管先は承認表に一致 |
| AT-17 | スマートフォンと切戻し | Chromium／WebKitのスマートフォン相当・320px・文字200%で操作可能。公開版を戻してもentryや会計を変更しない |

架空データの操作確認と実業務の受入を分ける。実装後も、権限付与・本番への配置・受付開始・外部への送信は承認済みの公開単位で進める。
