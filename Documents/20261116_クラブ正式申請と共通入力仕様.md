# クラブの正式申請と共通入力仕様

更新日：2026年11月16日。対象は `/manage/` のクラブ受付準備C1～C4です。今回の配置でも受付は開始しません。

## 確定した方針

出典は[既存回答表](https://docs.google.com/spreadsheets/d/1z0WuTupTRBSXgzMNBRjosTNgOi13HyVPYtn1knIsato/edit#gid=202611011&range=A111:I119)のF08・N09・L01・L02・N12と、11月16日の依頼者の指示です。L01・L02は回答受領済みの内容を再確認しました。

| 項目 | 仕様 |
| --- | --- |
| 申請前の確認 | 事務局による事前確認や代表者権限の付与を、申請の条件にしない |
| 受付範囲 | 新規・更新・再加入、正会員・賛助、関連団体・企業を含む |
| JAF番号・区分 | 本人が5桁のJAF登録番号と区分を申告し、申請後に事務局が照合する。番号・区分が誤っていれば理由を添えて差し戻し、本人が訂正して再申請する |
| 既存クラブ | クラブ名・正式略称・コードで更新候補を表示する。未選択でも申請できる。候補を選ぶだけでは既存クラブの権限を付与しない |
| 更新の確認 | 「更新」は事務局の照合待ちとして保存する。既存年度への接続は、事務局の確認後に行う |
| 受付と正本 | クラブ受付は2026年12月1日に先行。個人会員受付と個人会費・年度資格の正本切替は2027年1月1日に同時実施する。今回、正本は `shadow` を維持する |

## 共通の文字整形

全角英字・全角数字・全角スペースを、同じ意味の半角文字へ整形します。例えば `ＡＢＣ１２３　Ⅲ` は `ABC123 Ⅲ` になります。`Ⅰ`・`Ⅲ` などのローマ数字、漢字、仮名、記号はそのまま保持します。ローマ数字まで変換するNFKCは使いません。

サーバー側では全ポータル画面の共通の初期処理でGET・POSTの配列値を再帰的に整形します。不正なUTF-8と深すぎる配列は拒否します。整形した後も、各項目の必須・桁数・形式・権限・CSRF・受付期間の検証、SQLの値の束縛、HTML出力時のエスケープを行います。文字を半角にしただけで安全な入力とは判定しません。

ブラウザー側も同じ範囲を整形します。日本語の変換中は処理を待ち、変換確定後・入力欄を離れたとき・送信時に整えます。JavaScriptを無効にして送った値も、サーバーで整形・検証します。

パスワード、署名、CSRF・QR等のトークン、申請の再送判定キー、確認画面の操作識別値、CSV原文とアップロード原本は、値の一致や原本保持が必要なため整形しません。配列のキーも変更しません。既存 `/entry/` のコード・設定は今回の変更対象に含みません。

実装は `src/Input/TextInput.php` と `public/manage/assets/input-normalization.js` です。[MDNのフォーム検証](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Form_validation)と[変換中の入力イベント](https://developer.mozilla.org/en-US/docs/Web/API/InputEvent/isComposing)を参照し、画面の補助とサーバーの検証を分けています。

## 正式入力と保存

クラブ・団体名称、正式略称、JAF登録番号、所属支部、JAF区分、正会員／賛助、新規／更新／再加入を保持します。所在地と郵便番号、クラブ電話、代表者の氏名・ふりがな・住所・郵便番号・電話・携帯・メール、連絡担当者の同じ項目を別々に保存します。会社・ショップ名とクラブ側の口座情報は任意です。

11月20日の共有レビュー(4)に合わせ、正式申請と操作確認画面は「クラブの情報」「代表者の情報」「連絡先の情報」の順に分けます。操作確認画面の番号欄は「JAF登録番号（5桁）」、近畿6支部以外の所属先は「他地区の場合の所属支部」と表示します。兼任の選択は連絡先欄より前に置き、同じ場合は再入力を省略できます。JavaScriptを使えない場合もサーバーで転記し、別の担当者の場合はサーバーで必須項目を検証します。保存キーと正規化順は変えません。

「代表者と同じ」を選ぶと、連絡担当者の情報をサーバーで転記します。会社名を除く確定必須項目、メール形式、郵便番号7桁、文字数等を検証します。不要とされたハンドブック関連の項目は保存しません。

入力内容と訂正前の履歴は、非公開設定の鍵を使って認証付き暗号で保存します。本人と既存の事務局承認権限を持つ人だけが申請内容を閲覧できます。他人の申請IDを指定しても参照できません。監査ログには操作と対象IDを残し、住所・口座・差し戻し理由の原文を記録しません。

追加する表は次の3つです。既存表の構造・既存業務行・既存アカウント権限は変更しません。

| 表 | 内容 |
| --- | --- |
| `portal_club_fee_profiles` | 年度・JAF区分・正会員／賛助別の年会費と新規入会金 |
| `portal_club_intakes` | 申請者・年度・区分・申請時料金・暗号化した正式入力・照合状態 |
| `portal_club_intake_revisions` | 訂正・差し戻し・年度接続前の暗号化履歴 |

同じ処理キーで同じ申請を再送した場合は、保存済みの1件を返します。同じキーで内容を変えた場合、古いバージョンで訂正した場合、同じクラブの年度登録を重複して接続した場合は拒否します。

## 事務局の照合

新規は提出済み、更新は照合待ちとして保存します。事務局は番号・JAF区分・正賛・登録履歴・申請者を確認します。誤りがあれば差し戻し理由を入力します。差し戻し中は年度登録へ接続できません。再申請すると理由は履歴に残り、再度確認の対象になります。

新規の固定5桁コードは、本人が入力したJAF番号と事務局が確認した番号が一致する場合だけ使います。更新・再加入は、事務局が既存ポータルクラブまたは旧エントリーのクラブを選び、番号の一致を確認します。旧クラブの場合はポータル側に対応を保存し、旧台帳は更新しません。

照合後は既存の `portal_club_years` と請求・承認処理へ接続します。照合した申請者はそのクラブの登録内容と請求を扱えます。この接続で実際の `CLUB_REP` 権限レコードは作成しません。個人会員の所属承認に使う代表権限の整備と受入確認は、C5～C6・M4の残作業です。

| JAF区分 | 正会員の年会費 | 賛助の年会費 | 新規入会金 |
| --- | ---: | ---: | ---: |
| 公認クラブ | 50,000円 | 50,000円 | 10,000円 |
| 加盟クラブ | 30,000円 | 30,000円 | 10,000円 |

新規入会金10,000円、更新・再加入0円は確定済みC08を維持します。関連団体・企業の入会金0円も維持します。L12の賛助団体年会費は回答待ちです。保存済みの申請・請求・入金は再計算せず、区分7のマスターと履歴も削除しません。区分7の新しい申請・承認は拒否します。

請求は申請時の年会費と入会金を合算し、既存のクラブ会費1明細へ接続します。内訳を説明に残し、年度クラブ単位の既存の一意制約で二重請求を防ぎます。クラブ用ペイメントコアURLは引き継ぎません。

実振込先が未登録なら請求を発行しません。満額入金と事務局承認がそろえば年度開始前の登録済み判定が可能ですが、年度資格の有効判定は正本・年度期間も確認します。入金訂正、停止、不足があれば再判定します。個人会員の支払済み判定と既存エントリーの会費を、クラブ会費で代用しません。

## 画面の確認方法

1. [JMRC近畿ポータル](https://gymkinki.com/manage/)に、現在のエントリーと同じアカウントでサインインします。
2. マイページの「クラブ登録の申請」を開きます。「受付開始前・準備中」の間は提出できません。
3. 更新するクラブがあれば、名称・正式略称・コードで候補を探します。候補にない場合は、名称等を手入力する方式です。候補を選んでも他クラブの情報は操作できません。
4. 登録方法・区分を選び、「会費だけ確認する」で金額を確認できます。この操作は申請・請求・入金記録を作りません。
5. 受付開始後は正式入力を提出し、自分の申請一覧から状況を確認します。差し戻された場合は、理由を読んで訂正し「訂正して再申請する」を押します。
6. 事務局は「事務局：提出済み申請を確認する」から申請を開き、照合または差し戻しを行います。年度接続と、入金確認後の年度承認は別の操作です。

今回の本番確認では提出・訂正・差し戻し・請求・入金の業務操作を行いません。画面の確認に本番の架空申請を作らず、操作試験は隔離環境で行います。

## 残る作業

C1はクラブの先行受付条件まで実装済みです。1月1日の個人受付・正本同時切替の実行方法、移行対象の照合、切替前後の総合受入は未完了です。独立した正本切替の操作は追加していません。

C2は事前確認を申請条件から外し、候補表示と申請後の照合経路を実装済みです。L02の2026年度クラブ一覧は提供済みとの回答がありますが、今回の接続済みDrive検索では対象を特定できていません。旧台帳は候補表示にだけ使い、未検査の資料を本番へ一括登録しません。共有URLの提供を既存回答表に追記しました。

C3・C4は正式入力・履歴・料金表と請求接続を実装済みです。C5の実振込先・手動入金の開始承認、C6の実担当者による受入、代表権限の整備は残ります。ライセンスの発行日への変更、個人氏名・住所の追加、Temporary・保険の開始範囲、正式会計、実メール送信、削除実行、一般公開は今回開始しません。

検証結果・配置範囲・復元手順は[検証と復元の記録](phase2/20261116_クラブ正式申請・検証復元.md)に記録します。
