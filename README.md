# JMRC近畿 事務局ポータル

JMRC近畿のクラブ登録、個人会員、所属承認、会員証、入金確認を、既存オンラインエントリーと共通のアカウントで扱うWebアプリケーションです。公開入口は [gymkinki.com](https://gymkinki.com/)、構築先は `/manage/`、既存エントリーは `/entry/` とする前提で開発しています。

現在は、確定した要件を隔離環境で実装・検証している段階です。本番への配置、DDL適用、実データ移行は行っていません。隣接する既存 `jmrckinki` リポジトリも変更していません。

## 確定した主要要件

| 領域 | 内容 |
| --- | --- |
| 共通認証 | 既存entryのusersとセッションを共用。追加権限はポータル側で管理 |
| 会員区分 | Generalは年2,000円、Temporaryはイベントごと500円。金額は年度別マスター |
| General | JAF競技・審判員ライセンスが必須。本人の有効なライセンスを選択 |
| Temporary | 主催クラブが承認。資格は開催日のみ、同日1イベント。Generalへの差額切替なし |
| クラブコード | 先頭の区分1桁と不変の5桁。1公認、2加盟、3準加盟、6加盟団体。年度内は固定 |
| General会員番号 | ライセンス番号-G-6桁クラブコード。採番元の変更後は旧QRを失効し、再発行方針は保留 |
| 資格の有効化 | 必要な承認、満額入金、クラブ資格、ライセンス、期間、アカウント状態を都度確認 |
| 会員証 | General本人に氏名・年度・番号・クラブ略称・ライセンス種類・QRを表示。Temporaryには発行しない |
| 入金 | ゆうちょCSVと手動確認。事務局・財務が入金確認と訂正を実施。曖昧な照合は自動確定しない |
| 入金先設定 | 事務局の専用権限で用途別口座・ペイメントコアURL・CSV実口座との対応を管理 |
| 制度 | 協議会見舞金、ジムカーナ部会救済基金、スポーツ安全保険を独立して扱う |
| 既存連携 | ポータルを対象年度の資格情報の参照元とする。救済基金の管理移管は未確定 |
| 対象外 | 過去エントリー履歴のマイページ表示、練習会・フォーラムの統合 |

主催クラブと代表アカウントは共通にできます。ただし、旧主催クラブと年度登録クラブの対応や承認済み権限を確認し、ログインしただけで管理権限を付与しません。

## 構成と検証

PHPとMariaDBを利用しています。Web公開ファイルは `public/manage/`、業務処理は `src/`、追加DDLと権限SQLは `design/phase2/`、既存entry用の連携コードは `integration/` に配置しています。設定と暗号鍵はWeb公開領域の外に置きます。

追加DDLは001～010の順に適用する構成です。[2027年度の受付日程案](design/phase2/2027_registration_calendar.proposal.sql)は通常の追加DDLと分けています。既存年度の上書きや本番への自動適用は行わず、資格情報の参照先も切り替えません。

本人情報訂正、保険意思受付、銀行CSV、入金先設定などの受付設定は既定で無効です。[設定例](config/auth.example.php)に従い、必要な権限と前提を確認した環境だけで有効にしてください。

隔離検証は次のコマンドで実行します。WSLのDocker環境と、テストで使用するNode.js依存が必要です。

```powershell
python tests/auth/validate_auth.py
```

架空データを使い、外部公開ポートのないinternalネットワークで検証します。既存entryの必要なコードだけをコピーし、原本のハッシュが変わっていないことも確認します。実ブラウザーはChromiumとWebKitのスマートフォン相当設定です。物理スマートフォンや本番の動作確認とは区別しています。

最新の結果は[検証記録](tests/auth/validation_result.json)、詳しい設計は[フェーズ2資料](Documents/phase2/README.md)を参照してください。過去の検証件数は各工程時点の記録であり、最新結果と合算しません。
