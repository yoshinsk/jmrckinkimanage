# 隔離MariaDB検証

対象: MariaDB 10.5.29、WSL UbuntuのDocker。`validate_schema.py`は本番接続機能を持たず、固定名・固定イメージの専用コンテナを起動する。公開ポートなし、network=none、DBはtmpfs、実行後に停止削除。既存Dockerコンテナには触れない。

```powershell
python design/phase2/build_ddl.py
python tests/phase2/validate_schema.py
```

Docker daemonが稼働していること、指定イメージを取得済みであることが前提。イメージはタグだけでなくdigestを固定。検証結果は `tmp/phase2_validation.json` に生成する。検証用コンテナ名が既に存在する場合は上書きせず停止するので、所有者と状態を確認する。

`legacy_schema.sql`は本番から読み取った10表と1ビューの定義のみ。AUTO_INCREMENTの現在値とDEFINER/元DB修飾を除き、隔離DBのINVOKERビューへ変換した。実レコード・接続情報は収録しない。架空アカウント、過去競技会、申込、会員、入金で検証する。

## 検証範囲

- 36表作成、再適用の既存表エラー、生成列一意制約、CHECK、外部キー。
- 年度/イベント/申請年度の一致、General/Temporary重複、現在所属/会員番号の一意性、他人の識別番号参照拒否。
- クラブscope実在/NULL全体scope重複、先頭ゼロ、未承認保存方針、親ユーザー削除拒否。
- 口座/取込一致、請求/銀行取引/消込/取消/通知の二重処理拒否、明細計算。
- 検証専用procedureで2接続が競合する消込の行ロックと超過拒否。これは本番用ストアドプロシージャではない。
- 保険年度/重複、旧10表+1ビューの定義と架空行の不変、空の別DBで逆順削除→再作成。

## DB制約だけでは保証しないこと

金額集計の上限、逆仕訳の元行と金額/対象の一致、返金残額、発行済み明細の上書き禁止、料金期間重複、資格の実期間、公開権限、保険提出人数はアプリサービスのロック/認可/検証が必要。検証用procedureは消込の一部だけを再現している。PHP/FPM共通ログインや帳票、運営未確定ルールの受入試験は未実施。

逆順削除SQLは**空の隔離DBでの構造検証用**。本番データのロールバックではない。新領域の申請・入金が発生した後の復旧には、台帳照合と保全が必要。
